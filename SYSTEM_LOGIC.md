# 🎯 WhatsApp Lead CRM - Логика системы

## Главный принцип

**Админка = Диспетчерский центр**

Все клиенты из WhatsApp **сначала попадают в админку**, где администратор их **распределяет операторам**.

## 📊 Полная схема работы

```
┌─────────────────────────────────────────┐

## 🔄 Пошаговый процесс

### Шаг 1: Клиент пишет в WhatsApp

Клиент видит рекламу и пишет **любое** сообщение:

```
Клиент: "Саламатсызба"
```

или

```
Клиент: "Хочу RF-лифтинг"
```

или даже

```
Клиент: "👍"
```

**Все эти сообщения обрабатываются!**

### Шаг 2: Evolution API отправляет webhook

```
POST https://api.yourdomain.com/api/v1/whatsapp/webhook
{
  "event": "messages.upsert",
  "data": {
    "key": {
      "remoteJid": "77771234567@s.whatsapp.net",
      "fromMe": false
    },
    "message": {
      "conversation": "Саламатсызба, хочу RF-лифтинг"
    },
    "pushName": "Алия",
    "messageTimestamp": 1691234567
  }
}
```

### Шаг 3: Backend обрабатывает (100% capture)

**LeadParserService автоматически:**

1. ✅ Извлекает телефон: `+7 777 123 45 67`
2. ✅ Извлекает имя: `Алия`
3. ✅ Сохраняет сообщение: `Саламатсызба, хочу RF-лифтинг`
4. ✅ Пытается определить процедуру по keywords: `RF-лифтинг` → **найдено!**
5. ✅ Берет цену из БД: `25,000 ₸`
6. ✅ Определяет период: `NIGHT` (если 19:00-09:00) или `DAY`
7. ✅ Проверяет дубликат webhook (защита от повторной обработки)
8. ✅ Создает/обновляет Client
9. ✅ Сохраняет сообщение в историю
10. ✅ **Создает Lead со статусом NEW**
11. ✅ **НЕ назначает оператора автоматически!** (ждет админа)

### Шаг 4: Лид появляется в админке

Админ видит в режиме **real-time** (WebSocket):

### Шаг 5: Админ распределяет оператору

Админ выбирает:

```
┌─────────────────────────┐
│ Выберите оператора:     │
├─────────────────────────┤

После нажатия:
- Lead.operatorId = Мария
- Lead.status = ASSIGNED
- Operator.currentLeads += 1
- WebSocket → Мария получает уведомление

### Шаг 7: Оператор звонит

Оператор:
1. Видит номер `+7 777 123 45 67`
2. **Берет свой обычный телефон**
3. **Звонит клиенту**
4. Разговаривает, уговаривает прийти

**Телефония НЕ интегрирована в систему!**

### Шаг 8: Оператор меняет статус

После разговора:

```
Статус: ● BOOKED

Заметка: "Клиент согласился, записала на завтра 15:00"

[СОХРАНИТЬ]
```

Backend обновляет:
- Lead.status = BOOKED
- Lead.notes = "Клиент согласился..."
- Operator.totalBooked += 1
- WebSocket → Админ видит обновление
- Lead учитывается в конверсии

## ⚠️ Особые случаи

### Случай 1: Процедура не определилась

Клиент написал:

```
"Саламатсызба"
```

Система создает:

```
Имя: Алия
Телефон: +7 777 123 45 67
Сообщение: Саламатсызба
Процедура: [НЕ ОПРЕДЕЛЕНА]
Цена: —
Статус: NEW
```

✅ **Лид всё равно создан!** Оператор сам выяснит по телефону.

### Случай 2: Клиент пишет повторно

Клиент уже в базе, но пишет снова:

```
День 1: "Здравствуйте"
День 3: "Хочу записаться"
```

Система:
- Client остается один (по телефону)
- **Создается 2 разных Lead** (2 обращения)
- Каждый Lead можно назначить разным операторам

### Случай 3: Дубликат webhook

Evolution API может отправить одно сообщение дважды.

Защита:
```typescript
// Проверка messageId перед обработкой
const duplicate = await checkDuplicateMessage(messageId);
if (duplicate) {
  return null; // Игнорируем дубликат
}
```

## 📊 База данных: Client vs Lead

**ВАЖНО:** Разделение Client и Lead!

### Client (Клиент)

```
id: uuid
phone: +77771234567 ← UNIQUE!
whatsappName: "Алия"
name: "Алия Сmagулова" ← может заполнить оператор
```

**Один номер = один Client**

### Lead (Лид/Обращение)

```
id: uuid
clientId: ref Client
operatorId: ref Operator
procedureId: ref Procedure
message: "текст сообщения"
status: NEW | ASSIGNED | CALLING | BOOKED | ...
period: DAY | NIGHT
```

**Один Client может иметь много Leads!**

Пример:

```
Client: +77771234567 (Алия)
  ├─ Lead #1: RF-лифтинг (BOOKED)
  ├─ Lead #2: Трихология (CALLING)
  └─ Lead #3: Массаж (NEW)
```

## 📈 Стратегии распределения

Backend **НЕ** распределяет автоматически! Админ делает это вручную.

Но если нужна автоматика в будущем:

### Round Robin
```
Лид 1 → Айжан
Лид 2 → Мария
Лид 3 → Ольга
Лид 4 → Айжан
...
```

### Least Busy
```
Айжан: 12 лидов
Мария: 8 лидов  ← новый лид
Ольга: 15 лидов
```

Настройка в `.env`:
```env
# По умолчанию выключено (ручное распределение)
LEAD_AUTO_ASSIGNMENT=false

# Если включить:
# LEAD_AUTO_ASSIGNMENT=true
# LEAD_ASSIGNMENT_STRATEGY=ROUND_ROBIN
```

## 🎯 API Endpoints для админки

### Получить все новые лиды (не назначенные)

```
GET /api/v1/leads?status=NEW

Response:
{
  "data": [
    {
      "id": "...",
      "client": {
        "phone": "+77771234567",
        "whatsappName": "Алия"
      },
      "procedure": {
        "name": "RF-лифтинг",
        "price": 25000
      },
      "message": "Хочу RF-лифтинг",
      "status": "NEW",
      "operatorId": null,  ← НЕ НАЗНАЧЕН
      "createdAt": "2026-08-08T19:42:00Z"
    }
  ]
}
```

### Назначить оператора

```
PATCH /api/v1/leads/{leadId}/reassign
{
  "operatorId": "operator-uuid"
}

Response:
{
  "id": "...",
  "operatorId": "operator-uuid",
  "status": "ASSIGNED",
  "operator": {
    "user": {
      "name": "Мария"
    }
  }
}
```
